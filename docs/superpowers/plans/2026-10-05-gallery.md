# PowerShell Gallery implementation plan

Goal: Make the existing toolkit installable and releasable as a module.
Architecture: one function implementation per command, compatibility wrappers,
allowlisted package staging, Windows validation before Gallery publish.
Tech stack: PowerShell 5.1/7, Pester, GitHub Actions, PSResourceGet.
Spec: ../specs/2026-10-05-gallery-design.md

## Constraints
- Keep Windows 5.1 support and credential format v1.
- Apache-2.0; module Apexfission.MavenTools version 0.1.0.
- No real credential/key operations or Gallery publish during preparation.

## Review focus
- Import must not execute native operations or leak helpers/preferences.
- Wrapper parameter binding and exit failures must remain intact.
- Native failures must not leak credentials or silently become success.
- Staged package must exclude local secrets and build/test state.
- Publishing must wait for both shells, match the tag and serialize uploads.

## Tasks
1. Add module tests: imports without gpg/gh, exact exports, help, parameter
   validation, namespace/fingerprint rejection, native failure, wrapper parity.
   Confirm missing module fails, convert code, rerun.
2. Add explicit package build and package-content tests; stage from allowlist.
   Validate manifest, import from staged path, compare file set, local publish.
3. Add Windows 5.1/7 CI and tag/manual publish with psgallery environment.
   Update README, command reference and release guide; remove typo launcher and
   stale repository links. Review YAML and verify all setup names agree.
4. Review full diff, run available verification, push feature branch and open PR.
   Report any unavailable verification separately from successful checks.
